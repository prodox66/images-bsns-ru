# images.bsns.ru

Статический хост публичной библиотеки изображений BZN.

## Развёртывание контента

1. Загрузить изображения через FTP в `images/`.
2. Запустить `node tools/build-image-library.mjs`.
3. Передать на сервер созданные `images/files.js` и `images/data/`, если генератор запускался локально.

На старом Node.js хостинга, который не поддерживает ESM, используется совместимый генератор:

`node tools/build-image-library-legacy.js`

## Автоматический запуск по FTP-триггеру

CRON раз в минуту запускает только быструю проверку:

`cd /var/www/u0318620/data/www/images.bsns.ru && node tools/reindex-on-trigger.js`

После завершения FTP-загрузки нужно повторно загрузить или изменить файл `images/REINDEX_LIBRARY.trigger`. Тяжёлая генерация выполняется один раз для новой версии триггера. Неизменённый триггер не сканирует и не перекодирует изображения. Состояние и lock сохраняются внутри исключённой из Git папки `images/`.

Вся папка `images/*` исключена из Git. Код сайта и генератор обновляются через Git. Runtime не использует PHP или базу данных.

Поддерживаются PNG, JPG/JPEG, WebP, AVIF, GIF и SVG. Общий Library Window показывает 30 изображений на странице.

## Resource Engine v2

Новый API и единая админская галерея находятся в `resource-engine/`. Они разворачиваются параллельно старому статическому индексу: старый FTP/trigger-маршрут остаётся рабочим до отдельного подтверждённого переключения.

Админка загружает ресурсы в один каталог `resources`, редактирует теги, хранит отдельные WebP-эскизы, выполняет ограниченную явную оптимизацию и перестраивает новый каталог. Типы `pictures`, `masks` и `shadows` пока используют этот общий источник; дальнейшая маршрутизация скрыта внутри resolver. Подключение, конфигурация и вызов редактора описаны в `resource-engine/README.md`.
